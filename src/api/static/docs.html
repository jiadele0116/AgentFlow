Multi-Agent System 技术文档

基于 LangChain + LangGraph + FastAPI 构建的多 Agent 协作系统。多个 AI Agent 分工协作，支持工具调用、知识检索、质量审查。

项目概述

这是什么

Multi-Agent System 是一个多智能体协作框架。与单个 AI 对话不同，这里的多个 Agent 各司其职：Planner 负责任务分解，Executor 负责执行（可调用工具），Critic 负责质量审查。不通过则回退修订。

💡
核心理念：复杂任务不是一个 Agent 能搞定的，需要分工协作、互相审查。

核心概念：LangChain

LangChain 是 LLM 应用的统一接口层。不同厂商的 LLM（Anthropic Claude、通义千问、OpenAI）API 各不相同，LangChain 提供统一的 BaseChatModel 接口，让你不用关心底层差异。

python
# 不用 LangChain：每个厂商写一套
anthropic_client.messages.create(...)
dashscope.Generation.call(...)

# 用 LangChain：统一接口
from langchain_core.language_models import BaseChatModel
from langchain_core.messages import HumanMessage

async def ask(llm: BaseChatModel, question: str):
    response = await llm.ainvoke([HumanMessage(content=question)])
    return response.content

# 传入 ChatAnthropic 或 ChatTongyi 都可以
answer = await ask(llm, "什么是 RAG?")

本项目中 LangChain 负责三件事：

  • 统一 LLM 调用 — src/llm/langchain_llm.py 根据配置创建对应的 ChatModel
  • 工具定义 — src/tools/langchain_tools.py 将 Python 函数包装为 LLM 可调用的工具
  • 消息格式 — 使用 HumanMessage、SystemMessage、AIMessage 标准化消息

核心概念：LangGraph

LangGraph 是 LangChain 生态的状态图框架，用于构建有状态的多步骤工作流。普通的 LLM 调用是一问一答，但多 Agent 协作需要：先规划 → 再执行 → 再审查 → 不通过还要回退。这就是 LangGraph 解决的问题。

python
from typing import TypedDict
from langgraph.graph import StateGraph, END

# 1. 定义状态（在节点之间传递的数据）
class MyState(TypedDict):
    task: str
    result: str
    approved: bool

# 2. 定义节点（处理函数）
async def do_task(state):
    return {"result": "完成了"}

async def review(state):
    return {"approved": True}

# 3. 构建图（节点 + 边）
graph = StateGraph(MyState)
graph.add_node("worker", do_task)
graph.add_node("reviewer", review)
graph.set_entry_point("worker")
graph.add_edge("worker", "reviewer")
graph.add_conditional_edges("reviewer", lambda s: "end" if s["approved"] else "worker")

# 4. 编译并运行
app = graph.compile()
result = await app.ainvoke({"task": "分析代码", "result": "", "approved": False})
✅
LangGraph 的核心价值：把"谁先执行、谁后执行、什么条件回退"这些流程控制逻辑，从代码中的 if-else 变成了可视化的图结构。

LLM 模块

LLM 模块的职责很简单：根据配置创建 LangChain ChatModel 实例。

python
# src/llm/langchain_llm.py

def create_langchain_llm(settings: Settings) -> BaseChatModel:
    provider = settings.llm.provider.lower()

    if provider == "anthropic":
        from langchain_anthropic import ChatAnthropic
        return ChatAnthropic(model=settings.llm.model, ...)

    elif provider == "qwen":
        from langchain_community.chat_models.tongyi import ChatTongyi
        return ChatTongyi(model=settings.llm.model, ...)

工具系统

工具是 Agent 能力的最小单元。LLM 本身只能生成文本，通过工具它可以：读写文件、执行代码、访问网络、搜索知识库。

注册机制

python
from src.tools.registry import ToolRegistry

registry = ToolRegistry()

@registry.register(
    name="read_file",
    description="Read the contents of a file",
    parameters={
        "type": "object",
        "properties": {"path": {"type": "string"}},
        "required": ["path"]
    },
)
async def read_file(path: str) -> str:
    with open(path) as f:
        return f.read()

Agent 系统

这是系统的核心——三个 Agent 分工协作完成任务。

状态定义

python
class MultiAgentState(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]  # 对话历史（自动追加）
    task: str                       # 用户任务
    plan: str                       # Planner 的计划
    execution_result: str           # Executor 的结果
    review_status: str              # "pending" / "approved" / "rejected"
    iterations: int                 # 修订轮次

三个节点

📋 Planner 节点

调用 LLM 分析任务，生成执行计划。输入用户的原始任务，输出分步计划。

⚡ Executor 节点

根据计划执行任务。可以调用工具（llm.bind_tools(tools)），获取工具结果后生成最终答案。如果被 Critic 拒绝，会收到修订指令。

🔍 Critic 节点

审查执行结果质量。回复 APPROVED（通过）或 REJECTED（不通过 + 原因）。

条件路由

python
def should_continue(state):
    if state["review_status"] == "approved":
        return "end"            # 通过 → 结束
    if state["iterations"] >= 2:
        return "end"            # 超过 2 轮 → 强制结束
    return "executor"           # 不通过 → 重新执行

图构建

python
graph = StateGraph(MultiAgentState)

graph.add_node("planner", planner_node)
graph.add_node("executor", executor_node)
graph.add_node("critic", critic_node)

graph.set_entry_point("planner")
graph.add_edge("planner", "executor")
graph.add_edge("executor", "critic")
graph.add_conditional_edges("critic", should_continue, {
    "end": END,
    "executor": "executor",
})

compiled = graph.compile()

RAG 模块

RAG（Retrieval-Augmented Generation）= 检索增强生成。让 LLM 在回答时参考外部知识库。

流程

文档入库：文档 → 分块(chunker) → 向量化(embedder) → 存储(vector_store)

查询检索：问题 → 向量化 → 相似度搜索 → 返回相关文档块 → 注入 LLM 上下文

核心组件

组件文件职责
TextChunkerchunker.py文档分块（默认 512 字符，重叠 64）
Embedderembedder.py文本向量化
VectorStorevector_store.py向量存储抽象接口
RetrievalPipelineretrieval.py完整检索管线

常见问题

Q: 如何切换 LLM 提供商？

修改 config.yaml 中的 llm.provider（anthropic 或 qwen）和 llm.model，并设置对应的环境变量。

Q: 如何添加自定义工具？

在 src/tools/builtin/ 下创建新模块，用 @registry.register(...) 装饰器注册，然后在 __init__.py 中调用。

Q: 如何修改 Agent 行为？

编辑 src/agents/langgraph_multi.py 中的节点函数的 SystemMessage 内容。

Q: 如何添加新的 Agent 节点？

在 MultiAgentState 中添加新字段 → 定义新的节点函数 → graph.add_node(...) → 添加边连接。
